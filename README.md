# 一餐 · 我的厨房（PWA）

把日常做得有滋有味——一个「一人食」小厨房：记住手边食材，安排一餐，采买、开火、盖章。
按 Figma 原型《一餐 · 我的厨房｜MVP 交互原型》V2 口径实现的**零依赖纯静态 PWA**。

## 结构

```
yican/
├─ index.html            入口（V2 口径：390 移动布局，桌面居中成一列）
├─ theme.css             主题契约 31 变量，值取自 Figma 实测 token（换风格只换此文件）
├─ styles.css            组件样式，只用契约变量
├─ manifest.webmanifest  PWA 清单（可添加到主屏、standalone）
├─ sw.js                 Service Worker，预缓存 + 离线可用
├─ js/
│  ├─ data.js            20 道菜 + 食材/调料/厨具字典
│  ├─ store.js           单一数据源：localStorage 持久化 + 推荐评分 + 收藏 + 库存四条铁律
│  ├─ icons.js           内联线性 SVG 图标（无 emoji）
│  ├─ views.js           全部界面（启动页/首页/我能做/收藏/菜谱/餐单/采买/入库/烹饪/落章/我的…）
│  └─ app.js             hash 路由 + 常驻悬浮玻璃胶囊底导 + 动作委托 + 自写确认弹窗 + SW 注册
├─ assets/img/           菜品图（20 道菜逐张补；未补的自动回退白盘蒸汽占位，不裂图）
├─ assets/icons/         SVG 应用图标（含 maskable 安全区版）
└─ scripts/              Node 冒烟测试（无浏览器依赖）
```

## 怎么跑

任意静态服务器即可（需要 http 才能注册 Service Worker，别用 file:// 直接打开）：

```bash
npm run dev        # = py -3 -m http.server 8848
# 打开 http://127.0.0.1:8848
```

手机和电脑同一 WiFi 时：服务器绑定 `0.0.0.0`，手机访问 `http://<电脑局域网IP>:8848`。
要「添加到主屏 / 离线」必须 HTTPS 或 localhost——线上用 GitHub Pages（自带 HTTPS）。

## 功能（当前范围）

- 首页：大标题「一餐」+ 右侧筛选小图标（带已选数量角标）/ 厨房入口 /「我能做」胶囊；下方「推荐菜品」两列流
- 推荐是可解释评分：食材厨具全齐马上能开火的置顶，其余按家里已有食材占比排，再按做过的菜学味型/类型微调；筛选抽屉按做法、味型、类型多选
- 「我能做」：只列马上能开火的菜（食材厨具调料全齐），顶部搜索框可搜全部菜名/食材
- 底部导航：悬浮白色玻璃胶囊（脱离底边、左右留白），灰色药丸随 tab 左右滑动（参照 BOSS 直聘）
- 启动页（1.4 秒自动进入，可点跳）
- 菜谱详情：顶部全宽出血大图（悬浮返回钮 + 右下角心形收藏），标题区一个「开始做菜」按钮，下方用料清单 + 完整分步做法
- 「开始做菜」自动分流：厨具未记录先确认（「家里有炒锅吗」），缺料生成采买清单，齐了直接进开火页
- 采买勾选 → 确认入库（显示 1 → 2 变化）→ 食材齐了 → 分步烹饪 → 确认消耗 → 落章动画
- 我的厨房：食材 / 常备调料（有·用完）/ 厨具（有·没有·未记录）管理
- 我的：收藏的菜、开火历史与印章；可重置为示例厨房或清空成空厨房
- 全部数据 localStorage 持久化（含收藏），刷新/重开不丢，可离线

## 库存四条铁律（已写进 store，并有测试）

1. 选菜不入账，「确认入库」才加库存；
2. 开始做饭不扣，「确认完成」才在同一动作里扣减并写历史/盖章；
3. 重复确认不重复记（同日同菜只一条历史、一天一章），可撤销并同步恢复库存；
4. 调料只在「有 / 用完」间切换，「用完」只能手动恢复，绝不被默认值覆盖。

验证：

```bash
node scripts/smoke.mjs         # 库存铁律等业务规则
node scripts/render-check.mjs  # 全闭环各屏渲染 + 关键文案
```
